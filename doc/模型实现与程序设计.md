# Weather99 模型实现与程序设计

## 1. 实现范围

以模块化单体落地现有设计。采集仍保存原始 JSON；策略核心只接收不可变领域对象，不读网络、数据库或系统当前时间。持久化采用本地 SQLite WAL，评估、连续确认状态和待分发事件同事务提交；未来需要多实例部署时，可替换存储适配器为 PostgreSQL，领域模型和纯计算接口无需改变。

| 模块 | 职责 |
|---|---|
| `domain.py` | 时间戳、四模型向量、预报、温度档、快照、风控状态、评估结果的不可变契约 |
| `config.py`、`config/strategy.json` | 运行参数校验、完整内容哈希版本；不读取文档里的历史账户状态 |
| `forecasting.py` | 滚动偏差、岭回归、误差尺度、训练制品、逐日向前验证 |
| `probability.py` | 温度区间解析、完整互斥分区校验、正态整数桶概率、观测下界条件化 |
| `strategy.py` | `evaluate(snapshot, config, risk)` 纯函数；记录每个候选的概率、成本、优势、拒绝原因 |
| `risk.py` | 日亏损、连亏、回撤和账户日期检查；否决权优先于信号 |
| `adapters.py` | 采集快照及文档格式到领域契约的转换；隔离外部字段变化 |
| `qweather.py`、`http.py` | 和风天气独立补充源；请求头认证、gzip、有限重试与凭据脱敏，不改变四模型特征 |
| `storage.py` | 不可变输入/配置/模型记录、幂等评估、连续确认、事务事件日志 |
| `service.py`、`cli.py` | 组织训练、采集、回放、审计；不包含数学公式 |

主流程：`collect → train（历史数据）→ analyze → evaluate → risk veto → confirmation → audit/event`。

本阶段输出研究信号。`execution_enabled` 始终为 `false`；未实现资金账本、订单状态机或交易所执行，也没有声称完成原架构的所有业务上下文。

## 2. 文档事实与实现假设

运行配置把文档可确认参数放进 `entry`、`risk`、`training`，新增研究假设放进 `research_assumptions`。配置全文哈希与模型版本一起写入结果，修改任一参数都会改变配置版本。

| 项目 | 当前实现 | 依据 / 限制 |
|---|---|---|
| 模型输入 | ECMWF、GFS、CMA、JMA 日最高温，严格四模型齐全 | 文档已确认；不以小时实测补充缺失模型 |
| 等权中心 | 四模型算术均值 | 文档已确认 |
| 滚动校准 | 最近 60 个日历日内历史样本，偏差 = 预报 − 实况；校准中心 = 当前等权 − 历史偏差 | 方向与窗口已确认；最少 60 个完整有效样本是保守实现选择 |
| 岭回归 | 最近 540 个日历日，四模型温度为特征，alpha=3，截距不惩罚；不标准化特征 | 窗口与 alpha 已确认；特征构造/标准化细节未公开，本实现为独立研究版本 |
| 分歧 | 四模型最大值 − 最小值 | 文档例子 17.8−16.9=0.9；精确定义未公开，明确作为假设 |
| 误差尺度 | `max(0.1, sqrt(0.4994 + 0.072 × disagreement²))` | 系数来自文档，0.1 下界为数值保护；未以自有历史重新估计系数 |
| 温度概率 | 正态分布；整数 k 的区间为 `[k−0.5,k+0.5)`；两侧尾桶保留全部尾部质量 | FMZ 精确概率族未公开，采用明确的研究假设 |
| 实测下界 | 当日 ZSPD METAR 中已观测最高温作为连续温度下界，条件化 `T >= observed_max` | 文档提到使用当日最高观测，具体条件化方式未公开 |
| 盘口概率 | 采集的 Yes outcomePrices 除以完整分区总质量 | 研究假设；不能将其当作可以成交的价格 |
| 融合 | `0.45 × 天气概率 + 0.55 × 盘口概率` | 55% 是文档单次快照值，固定权重是研究选择；配置验证不超过 85% 上限 |
| 成本 | 每个选中互斥桶买一份 Yes，成本 = 卖一价之和；任一桶中奖支付 1 USD | 独立明确的等份组合口径；不假定任意规模可按卖一全部成交 |
| 净优势 | 天气概率 − 卖一价之和 − 0.01 − 0.005，单位为每组份额的 USD | 预留比例来自文档；固定按 1 USD 支付额预留和优势公式均为研究选择 |
| 组合枚举 | 全部 1～3 桶组合，按净优势排序，在全部门槛通过者中选最佳 | 是否必须相邻等细节未公开；因此未声称候选与 FMZ 完全一致 |
| 价差/价格过滤 | ask 在 [0.01,0.99]，spread≤0.10；拒绝单边和交叉盘口 | 文档仅明确存在过滤，具体限值未公开，默认值列为研究假设 |
| 新鲜度 | 盘口及预报采集不超过 300 秒；当日最新观测不超过 1 小时 | 工程上的保守门槛，不是 FMZ 已知规则 |
| 众数约束 | 必须包含盘口众数；天气与盘口众数档间距≤2°C；尾档按区间最近距离处理 | 约束来自文档；尾档和并列众数处理是实现选择，并列时确定性选较低档 |
| 连续确认 | 同日期/时间层、相同配置、模型版本及选中组合，两个时间递增的合格快照；间隔≤1800秒 | 确认次数来自文档，窗口和身份定义是研究选择 |
| 风控 | 当日已实现≤−5 USD、连亏≥3、回撤≥30%时否决 | 文档参数；账户状态必须单独提供，缺失或日期不匹配则否决 |

四个时间层概率门槛分别为 55% / 50% / 50% / 52%，净优势门槛为 5% / 3% / 2% / 2%。风险否决不抹去候选计算，便于解释“信号合格但账户停机”。

注意：文档分歧 0.9°C 代入公开误差公式得到约 0.747°C，与页面展示的 0.8°C 并不完全相同。`demo` 保留页面记录的 0.8°C；重新训练后的预测按公式计算。本项目不会为对齐单个展示值静默修改公式。

## 3. 训练样本与防止未来信息泄露

历史输入是 JSON 数组，每条记录结构见 `examples/history.sample.json`，其中只是格式示例，不能满足训练样本量要求。

- `target_date`：上海当地目标日。
- `issued_at`：该模型向量实际可获取的时间，必须带时区。24h 样本必须在目标日前发布；日内层允许目标日当天发布。
- `models_c`：四个模型在该发布时间对目标日最高温的预报，按模型名称绑定，不能用事后重分析数据替代。
- `settled_at`：正式结算值实际可获取的时间，必须在目标日结束后，训练时不得晚于截止时间。
- `actual_c`：正式核验的最高温，要求与目标市场的站点、单位、结算口径一致。程序检查格式，来源真实性仍依赖采集流程。
- `station`：当前限定 ZSPD。
- `layer`：24h / 12h / 6h / 3h；各层独立训练，禁止混用。同一层同一天有多个 vintage 时必须在输入准备阶段明确选择一条，程序不会静默覆盖。

训练只用目标日在截止日期之前、且结算已知的数据。`walk_forward` 逐日把 cutoff 放到测试样本的 `issued_at`，每次重新拟合；当前测试日实况只用于计算最终验证误差，不能影响本次模型。

训练产物包含训练范围、样本数、每模型偏差、等权偏差、校准后样本内 RMSE、岭系数、截距、全部训练选项、训练数据哈希和制品哈希。文件用独占创建保存，不覆盖旧版本；加载时核对哈希。样本内 RMSE 与逐日验证 MAE 分开命名。

目前历史输入通过文件导入；尚未实现历史 forecast vintage 和正式结算值的自动回填。不会用文档里的 −1.055 偏差、17.94 增强中心或 0.76 MAE 冒充自有模型的训练结果。

## 4. 数据与时间约束

支持整数 °C 的 exact / range / or below / or higher 桶。区间必须互斥、无缺口且含两侧尾档；不完整市场直接拒绝，不把局部桶重新归一化来隐藏缺口。每个桶的盘口概率必须存在，执行成本始终使用 CLOB ask。

实时适配器核对站点、事件身份、事件状态、明确截止时间、预报时间、book 时间和模型时间层。模型训练时间不能晚于待回放快照。目标日为今天时，仅取上海当地同日、ZSPD、时间不晚于快照的观测来确定最高温下界；它不是正式结算值，也不要求这些离散报文覆盖全天。

时间层通过 `--layer` 显式指定。FMZ 的分层切换时刻没有公开，本阶段不从 UTC 截止时间猜测 24h/12h/6h/3h 调度；调用方应使用与历史样本相同的 vintage 选择规则。自动调度留待规则明确后加入。

## 5. 幂等、连续确认与回放

`evaluate()` 返回纯计算结果，`AuditStore.record()` 处理持续状态。每条评估绑定完整输入、源快照、风控状态、配置版本和引擎版本。同一输入重复运行返回同一记录，不新增事件、不增加确认次数。

同一日期/时间层按递增快照时间处理。拒绝会重置连续确认，超时、配置变更、模型变更或组合变化会重新从一次开始；同一时间不同快照和乱序回放不会改变较新的确认状态。需要重新做一轮时间顺序回测时，应使用独立数据库。

SQLite 事务内写入评估、确认状态与 `domain_events`。事件表是本地待分发日志，本阶段没有后台消费者、交付重试或交易执行；“confirmed_research_signal”只代表连续通过研究门槛。

`demo` 直接读取文档记录的增强中心/误差尺度，型号标记为 `recorded_document_estimate_not_trained`。缺少历史账户最高权益，因此不伪造风控状态。它可以检查概率与拒绝原因，不等价于 FMZ 源码重现或真实收益回测。
